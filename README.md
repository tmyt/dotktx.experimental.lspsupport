# DotKtX.Experimental.LspSupport

Experimental [JetBrains Kotlin LSP](https://github.com/Kotlin/kotlin-lsp) support
for editing [DotKt](https://github.com/tmyt/dotkt) projects. The package adds an
MSBuild target that writes `workspace.json` with DotKt's CLR standard library
and the reference KLIBs published by `DotKtResolveKlibReferences`. The Kotlin
language server reads those KLIBs directly for completion, diagnostics, hover
and go-to-definition.

## Usage

Use DotKt SDK and Toolchain `0.9.35` and Kotlin LSP `271.2085.0` or newer.
Kotlin by JetBrains for VS Code bundles that server starting with extension
`0.0.86`. [Kotlin LSP release notes](https://github.com/Kotlin/kotlin-lsp/releases/tag/kotlin-lsp/v271.2085.0)

Add the package as a private build dependency.

```xml
<ItemGroup>
  <PackageReference
    Include="DotKtX.Experimental.LspSupport"
    Version="[0.9.18]"
    PrivateAssets="all"
    IncludeAssets="build" />
</ItemGroup>
```

Add these entries to the project’s `.gitignore`.

```gitignore
.dotkt/
workspace.json
```

Run `dotnet build`, then open the project directory in VS Code with the Kotlin
extension. Set `intellij.buildTool` to `json` if you need to select the importer
explicitly. DotKt remains responsible for compiling and running the project.

## Workspace model

```text
workspace.json
.dotkt/lsp/
├── .stamp
└── compatibility/java/io/Serializable.kt
```

The generator uses the language server's common Kotlin analysis platform. It
registers the original CLR standard library and assembly reference KLIBs in a
single library, so the editor can resolve both `kotlin.clr` and CLR APIs with
their original metadata. Go-to-definition can open the corresponding
decompiled KLIB declaration. The analysis-only `java.io.Serializable` marker
satisfies a supertype lookup the common analyzer makes for types such as
`Int` and CLR enums. The MSBuild integration excludes that source from DotKt's
compiler inputs. The workspace enables companion blocks for CLR static members
and passes Kotlin compiler plugin paths registered through `DotKtCompilerPlugin`
to the analyzer so it can resolve types such as Compose lambda parameters.
It also opts in to `kotlin.ExperimentalUnsignedTypes` for analysis, matching DotKt.

The build replaces an existing workspace generated by this package and removes
the old projection JAR, stubs and report. A user-authored `workspace.json` is
protected. From `0.9.12` onward, the workspace includes the references resolved
by DotKt, so the former `DotKtxExperimentalLspJavaProjection` policy no longer
applies. Use the preceding `0.9.11` package if you need the previous JVM
projection.

Set `DotKtxExperimentalLspSupportEnabled` to `false` to disable generation.
`DotKtxExperimentalLspRoot` defaults to `.dotkt/lsp` and can be set to a
different directory for generated files. `dotnet clean` removes the generated
workspace and compatibility source.

## Development

The generator is a .NET 10 command-line tool. The Kotlin fixtures in
`tests/Smoke` and `tests/ReceiverFixture` build with the DotKt SDK pinned in
`global.json`. Building the fixtures requires a JDK for the DotKt compiler.
Verification also uses Node.js and `unzip`.

```bash
bash scripts/build.sh
bash scripts/pack.sh
bash scripts/verify.sh
node tests/Smoke/verify-lsp.mjs
```

`pack.sh` creates the NuGet package under `artifacts/packages/`. `verify.sh`
builds through the package reference, checks the generated model against the
resolved KLIB list, runs the Smoke program, and verifies migration,
incremental generation and cleanup. Logs are written to
`artifacts/verification/`. Extra MSBuild properties can be passed to the shell
scripts, for example `-p:RestoreAdditionalProjectSources=/path/to/local/feed`.

The Node verifier starts the installed Kotlin language server and exercises
CLR completion, definition and decompilation, type inference and diagnostics.
It also verifies that JVM- and JS-only APIs and JS `dynamic` are rejected in
the analysis model. Set `KOTLIN_LSP_SERVER` to use a standalone server.
